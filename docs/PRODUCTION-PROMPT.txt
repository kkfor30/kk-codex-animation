一、技术与确定性

- 使用 Remotion 4.0.529、React / React DOM 19.2.3、TypeScript、roughjs 4.6.6。所有 Remotion 包保持同版本，保存 lockfile。使用当前环境能运行的 Node.js；音频可以用 Python + NumPy / SciPy + FFmpeg 离线生成。
- 动画由 useCurrentFrame() 和共享状态函数驱动；禁止实时计时器、依赖播放次数的状态累积、CSS 无限循环和无种子的 Math.random()。固定随机种子 20260928，纹理在初始化时生成，不能每帧闪烁。
- 逻辑画布1600×900，等比输出1920×1080。Composition 的 durationInFrames=900、fps=30，合法帧0–899。下文“帧”一律指这900帧中的输出帧，不能另建故事时间后漏做映射。
- 建立一个 getSceneState(frame)，集中计算角色、肩部、手、道具、素材、字幕、参数、播放头、镜头、气泡、点赞数和声点。组件读同一个状态，不能各自猜动作时刻。
- 建立统一 events 数据；所有接触、切割、释放、落地、转场、键入、拖动、吸附、导出和点赞事件都从这里读取，画面和声音共用。
- 视频故事时钟是30秒；界面内被编辑素材的时间轴是另一套素材时间。两者明确区分，顶栏显示故事时间，素材轨播放头依据素材播放状态计算。
- 背景配乐从故事第0帧开始连续播放；界面中的音乐条在四段素材落位后才出现。二者不是同一条可见性规则，不能因为音乐条尚未展开就让片头无声。

需要延长手臂时，仅处理正在操作的一侧：

- 保留原躯干、双腿和另一侧手臂。先识别原肩部与手臂的实际像素范围，再局部遮除被替换的原手臂；遮罩不能误伤躯干或肩部。
- 延伸手臂的根部进入原肩部下方，由原身体轮廓覆盖连接处。不得切掉肩部形成白缝，不得残留旧手掌、断线或形成第三只手。
- 新手臂使用连续曲线、柔和弯曲和向手腕逐渐变细的轮廓，颜色、描边粗细与阴影接近原精灵。手掌与手腕连成整体，避免大圆球手掌或等宽长条直接贴在原手上。
- 手臂可以有适量卡通伸缩；较远目标先让身体靠近。接近、伸手、抓握和回收连续进行，不瞬移，不在切换姿态时改变身体比例，不把整张精灵拉长。
- 活动手掌与被握住的卡片、刀柄或旋钮共用坐标。道具释放后使用独立弹道，手先收回；操作结束自然回到官方正常姿态。
- 墨镜、汗滴、惊讶符号是可移除图层，不能覆盖所有表情。需要额外表情时优先复用官方表情，不借机重新设计身体。
- 角色缩放、屈膝、跳跃和换姿态后，重新核对脚底与地面、阴影的关系。

正式用于全片前，生成角色动作检查图：正常站立、向左抓取、向右抓取、向上拉滑块、向下切割、收手。正常姿态与官方原图并排查看；至少逐帧检查一次完整伸手和收手，并放大肩部、手腕及道具抓握处。只看全景缩略图不算角色验收。发现断口、重复肢体或风格不一致，先修共享角色组件，再进入整片。

字幕与气泡的不可遮挡规则

手机内“前方高能”放在柴犬头顶上方的空白区：手机内部中心x180，安全框x22..338、y70..160；四字字号约58–62，按真实字体测宽自适应。深墨4px左右描边、金黄色填充，可加低透明深色圆角底。文字不盖眼睛、鼻子和脸，顶部不碰听筒。错误字“熊”与改正字“能”使用完全相同的位置，不能纠错后跳到胸口。

纠错的“这回对了！”气泡放到手机右侧空白区，建议世界框x965..1195、y420..482，尾巴指向角色头部；“已修正”小章放x970..1150、y355..402。这些是初始建议位置，允许根据实际头部和气泡包围框微调，但二者不得与手机世界矩形x704..936、y103..514相交，也不得挡右侧参数、彼此重叠或遮住角色脸部。

所有气泡本体和尖角使用角色经过位移、跳跃、倾斜后的同一世界坐标。先根据安全区摆放气泡本体，再让尖角指向头部上缘附近的实际锚点，不能固定使用偏向左下的尖角。尖角落点可以在头部轮廓外留很小间距，但方向必须明确指向说话角色，不能指向肩外或手机。

其余气泡也要检查目标、道具、字幕和当前参数数值的碰撞，尤其是角色运动的中间帧和调参极端状态。单纯提高字幕 z-index 不是修复：即使它在手机内最上层，也会被手机外的角色气泡盖住；必须调整空间位置。所有镜头与片尾复用同一安全规则。

4.1 片头、视频导入与音乐展开

片头纸面中央出现约980×259的代码窗，Codey抱电脑坐在窗边。三行代码：

const 剪辑软件 = KK.写代码();
剪辑软件.画出(时间轴, 预览, 面板);

六、音乐与动作声音从零制作

不要寻找某台电脑上的原曲或声效，不声称文字能恢复一首未知录音。新建音乐母轨、动作音效分轨与最终混音；音乐和音效分别调节。音乐应有完整编曲，轻快、俏皮、有推动力，带电子 funk / 游戏配乐气质，不要刺耳蜂鸣器或只有鼓点的节拍器。

6.1 配乐规格

144 BPM，4/4，30秒正好18小节，每小节1.666667秒；第0秒为起拍。A小调，暖短拨弦/电钢琴主旋律、圆润低音、紧凑底鼓与军鼓、闭镲、轻和声铺底。统一节奏贯穿片头与剪辑，片头只减编配，不突然换歌或倍速。第21–24秒保留可听见的强拍，第27秒开始收尾，最后一小节回主和弦，尾音在30秒前自然结束。

有已可用音乐生成工具时按上述规格生成，检验真实速度与起拍，下载本地。没有该能力则直接离线合成一首完整多声部短曲，不让用户提供账号或密钥。离线编曲采用固定种子，至少包含鼓、贝斯、和弦、旋律四个独立声部：

- 四小节和声循环：Am7 / Fmaj7 / Cmaj7 / G6；第17、18小节 E7 → Am 收束。
- 鼓：每拍底鼓，第二/第四拍短军鼓或 rim，八分闭镲有强弱，少量反拍开镲；每四小节末用短fill，不压过切刀声。底鼓用低频扫频加短瞬态，军鼓用带通噪声加短共振，镲用高通噪声；不同声部不能都是同一个正弦音。
- 贝斯以A2/F2/C3/G2根音和五度做八分切分，保留休止。和弦短促反拍，旋律用E5–G5–A5–C6等和弦内音写“短问句—休止—短答句”，两小节呼应，别连续爬音阶。
- 合成音色使用不同泛音、ADSR、轻微滤波、立体声短延迟；鼓居中、伴奏适度左右分布。编配有开头减法、中段进入、卡点段重音、结尾解决，不能把一个一秒loop直接重复30次。

合成分支是独立新曲，听感未必等于专业音乐生成，应在交付说明使用哪种方式。无论来源，只有检测真实音频与试听后才能说卡点和混音已检查；如未能实际试听，按第七节如实标注。

6.2 动作音效

按统一事件表现场生成/制作独立短声音，不需要外链音效库：

- 纸片抓取与音乐条展开：细碎带通噪声、短纸声，展开末端落定有轻反馈。
- 美工刀：两次短锐“嚓”，从194和205帧开始，覆盖各自下切过程，不能使用两声与刀运动脱节的“叮”。
- 抛出与入桶：短带通whoosh；入桶纸响加低短碰撞。
- 投篮进框：空心轻弹加网声；翻页：有包络的纸声。
- 键入：短键击；Ctrl+Z：低一点的按键声。
- 滑块：轻摩擦加停靠click；磁吸：有冲击的短“咔”。
- 导出撞击：低钝碰撞；完成：柔和两音提示。
- 片尾点赞：少量轻弹或click，达到10万+时短促成功反馈，不淹没音乐收尾。

不要所有操作都配同一个“叮”。声效瞬态对齐实际接触、释放、入桶、到位帧；至少覆盖四次素材落地、音乐展开与落定、两刀、释放与入桶、两次转场、逐字输入/撤销/改正、各次拖动与停靠、按钮、三次吸附、导出撞击与完成、片尾点赞里程碑。

每个关键动作前约40–50ms开始让BGM短暂下降3–4dB，音效后约150–220ms平滑恢复；键击连串合并成一个ducking窗口，不每帧抽吸。音效不能被低音与高频镲淹没，也不能整片比音乐更吵。音乐不要重复叠加两份，混音不能简单硬剪到[-1,1]掩盖削波。

输出48kHz立体声，MP4用AAC。测量整片响度参考−15至−13 LUFS，编码后True Peak控制在−1dBTP左右或更低；数值只是参考，必须实际试听裁剪、翻页、磁吸和音乐是否能分辨。测完音频起点、强拍，再让beatMap与它一致。保存音乐和音效分轨，便于之后单独换曲。
