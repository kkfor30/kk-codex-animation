一、技术与确定性

- 使用 Remotion 4.0.529、React / React DOM 19.2.3、TypeScript、roughjs 4.6.6。所有 Remotion 包保持同版本，保存 lockfile。使用当前环境能运行的 Node.js；音频可以用 Python + NumPy / SciPy + FFmpeg 离线生成。
- 动画由 useCurrentFrame() 和共享状态函数驱动；禁止实时计时器、依赖播放次数的状态累积、CSS 无限循环和无种子的 Math.random()。固定随机种子 20260928，纹理在初始化时生成，不能每帧闪烁。
- 逻辑画布1600×900，等比输出1920×1080。Composition 的 durationInFrames=900、fps=30，合法帧0–899。下文“帧”一律指这900帧中的输出帧，不能另建故事时间后漏做映射。
- 建立一个 getSceneState(frame)，集中计算角色、手、道具、素材、字幕、参数、播放头、镜头、声点。组件读同一个状态，不能各自猜动作时刻。
- 视频故事时钟是30秒；界面内被编辑素材的时间轴是另一套素材时间。两者明确区分，顶栏显示故事时间，素材轨播放头依据素材播放状态计算。

字幕与气泡的不可遮挡规则

手机内“前方高能”放在柴犬头顶上方的空白区：手机内部中心x180，安全框x22..338、y70..160；四字字号约58–62，按真实字体测宽自适应。深墨4px左右描边、金黄色填充，可加低透明深色圆角底。文字不盖眼睛、鼻子和脸，顶部不碰听筒。错误字“熊”与改正字“能”使用完全相同的位置，不能纠错后跳到胸口。

纠错的“这回对了！”气泡放到手机右侧空白区，建议世界框x965..1195、y420..482，尾巴指向角色；“已修正”小章放x970..1150、y355..402。二者不得与手机世界矩形x704..936、y103..514相交，也不得挡右侧参数。其余气泡也要检查目标、道具和字幕的碰撞。单纯提高字幕 z-index 不是修复：即使它在手机内最上层，也会被手机外的角色气泡盖住；必须调整空间位置。所有镜头与片尾复用同一规则。

4.1 片头与导入

片头纸面中央出现约980×259的代码窗，Codey抱电脑坐在窗边。三行代码：const 剪辑软件 = KK.写代码();、剪辑软件.画出(时间轴, 预览, 面板);、KK.钻进屏幕().开工();。第33帧前写完，完整停到第55帧，再推进/融入工作台，第72帧完成。文字要可读，不能高速闪过；背景音乐从开始就是同一首连续乐句。

随后 Codey 依次抓四张卡片，接触后沿弧线搬到轨道，落地帧93、113、133、153，有轻弹和短金色星光。每次先伸手、接触、跟随搬运、落地、松手。初始视频轨四段边界x为120、390、860、1130、1470。对应宽270、470、270、340。手机由占位变落日。咖啡从进轨道起，中间x600..750就标出失焦灰纹区域，不能到挥刀时才凭空制造坏片。

4.2 有原因的裁剪与真实入桶

角色把播放头移入咖啡坏片，约第173帧手机先模糊、褪色、转圈并出现“对焦中…”。角色思考：“这段在发呆 zzz”。取美工刀，刀尖到轨道y692，分别在第198、205帧接触x600、750后切开，每刀配短裁切声、小火花和极轻反冲。先接触后产生切口；两刀之间150宽灰色废片与原位置一致。

角色抓废片上缘提起，第230帧松手，向垃圾桶抛出。桶位于世界(1120,540)，口约y472、底约y548。废片从约(675,620)到(1120,512)，抛物线上拱约175，旋转约310°，接近桶口时缩到0.35；第248帧入桶。分层顺序为桶后壁、飞行废片、桶前壁，桶前壁真实遮挡废片，落入后不从桶侧或底穿出。纸声、碰撞声与桶轻晃、合盖同步。角色手在释放后收回，不能继续跟随飞行废片。

4.3 裁剪后的素材连续性——重点实现

入桶后才在第249–263帧执行 ripple delete，把150宽空缺连续合拢。左段咖啡保留x390..600，右段原x750..860移动到x600..710；柴犬与舞台及关联转场、文字锚点统一左移150。最终四段边界为 120、390、710、980、1320，相邻素材必须无缝接触。

数据连续：咖啡仍是同一个 clipId 和同一个源场景，保存保留的 sourceRanges（源逻辑位置0..210、360..470）；编辑后的时间通过分段映射跳过废片，不能通过裁掉一张“时间轴截图”冒充剪辑。坏片状态只属于被删的源范围，删除后预览不能再进入失焦段。

外壳连续：闭合后咖啡是一条宽320的统一素材条，只有一个外圆角边框和一个“咖啡.mp4”标签；剪接处至多留1px细线。禁止保留两个各自圆角的盒子造成中间凹口、重复粗黑边、白缝、灰条、空白尾片，或重复两次文件名。合拢过程中右段整体运动，闭合时外壳切换必须几何一致、不跳动。

缩略图连续：用整条剪后clip的统一缩略图网格与源时间映射生成，格子连续铺满剩余宽度，最后一格自然裁切。不要每个碎片各自重置背景平铺原点、拉伸残余截图、重复半张杯子，或合拢完突然换一组缩略图。若咖啡为近静态镜头，可统一取稳定代表帧再铺排；一致性优先于无意义的缩略图变化。相邻正常源帧保持同机位、同杯子、同拉花和接近运动相位，不能剪掉模糊段后视觉上变成另一杯咖啡。

手机恢复清晰，角色笑：“清爽！”。检查切后前、中、后连续帧，不能只在最后一帧看起来拼好。

4.4 两种真实转场

转场页打开，角色抓橙色篮球转场令牌，第282帧投出；球走弧线，第296帧真正进入第一接缝x390,y691的篮圈，篮网、小星光、角色“好球！”响应，手机才从落日以金边圆形扩散转到咖啡。不能进框前就换完画面。

第二个紫色翻页令牌由角色送到咖啡/柴犬接缝x710，第330帧接触后才执行翻页：咖啡旧图往右折窄，折边有亮面和短阴影，柴犬图在后面显露。两个转场存到片段连接关系中；接缝位置后来变化时一起移动，卡点试听和片尾回放也要执行，不能只在添加时演一遍。

4.5 字幕输入、撤销、改正

角色将文字牌拖到柴犬对应文字轨；手机是柴犬。第369、377、385、393帧依次输入“前 / 方 / 高 / 熊”；时间轴与手机同时更新，最后“熊”变粉红并有短红下划线。字幕始终在头顶安全区。

第400帧角色发现错误，慌张、汗滴，气泡“能？怎么打成熊了！”。出现实体 Ctrl+Z 键，手接触后第423帧压下，只删除最后一个“熊”，留下“前方高”；保持这个真实中间状态至第440帧，第441帧再键入“能”。第450帧出现“已修正”章和“这回对了！”气泡，角色开心；章和气泡都在手机右侧，不盖四个字。

五、角色表演、镜头与光效

每个操作都按“看向目标 → 准备 → 伸手 → 接触 → 操作 → 反馈 → 松手”执行。手与抓住的卡片共用坐标，刀尖与切口共用接触点，手与旋钮共用数值映射。道具释放后单独走弹道，角色手先收回。动作不能靠气泡解释补齐。

身体会前倾、后仰、屈膝、落地压缩；开心、慌张、思考、放松能通过眼睛与姿势看出来，不能全片只有默认脸。常规移动用平滑三次曲线，落地与按钮用小阻尼回弹，持续拖动不反复超调。

所有内容放同一世界坐标系，用整体camera做局部聚焦；气泡也跟随该世界。全景建立与收尾，裁剪约1.29倍/中心(835,470)，纠错约1.32倍/中心(940,355)，参数约1.42倍/中心(1025,365)，卡点约1.12倍/中心(820,480)，导出约1.23倍/中心(940,370)。这些是起始构图，按实测包围盒微调：纠错镜头必须同时包含手机头顶字幕、角色、Ctrl+Z及右侧气泡，不能机械采用坐标而裁掉字幕。镜头提前到位，动作看完后再离开，平移和缩放一起缓入缓出，避免全程呼吸缩放。

灯光用于反馈：落地少量星光，切刀短暖闪，投篮圆弧辉光，过饱和影响整个台面，磁吸和播放强拍点亮素材边框与手机。保留纸面、墨线、字的可读性，禁止大面积持续纯白闪。强冲击只出现于接触之后，并快速衰减。

六、音乐与动作声音从零制作

不要寻找某台电脑上的原曲或声效，不声称文字能恢复一首未知录音。新建音乐母轨、动作音效分轨与最终混音；音乐和音效分别调节。音乐应有完整编曲，轻快、俏皮、有推动力，带电子 funk / 游戏配乐气质，不要刺耳蜂鸣器或只有鼓点的节拍器。

配乐规格：144 BPM，4/4，30秒正好18小节，每小节1.666667秒；第0秒为起拍。A小调，暖短拨弦/电钢琴主旋律、圆润低音、紧凑底鼓与军鼓、闭镲、轻和声铺底。统一节奏贯穿片头与剪辑，片头只减编配，不突然换歌或倍速。第21–24秒保留可听见的强拍，第27秒开始收尾，最后一小节回主和弦，尾音在30秒前自然结束。

有已可用音乐生成工具时按上述规格生成，检验真实速度与起拍，下载本地。没有该能力则直接离线合成一首完整多声部短曲，不让用户提供账号或密钥。离线编曲采用固定种子，至少包含鼓、贝斯、和弦、旋律四个独立声部：

- 四小节和声循环：Am7 / Fmaj7 / Cmaj7 / G6；第17、18小节 E7 → Am 收束。
- 鼓：每拍底鼓，第二/第四拍短军鼓或 rim，八分闭镲有强弱，少量反拍开镲；每四小节末用短fill，不压过剪刀声。底鼓用低频扫频加短瞬态，军鼓用带通噪声加短共振，镲用高通噪声；不同声部不能都是同一个正弦音。
- 贝斯以A2/F2/C3/G2根音和五度做八分切分，保留休止。和弦短促反拍，旋律用E5–G5–A5–C6等和弦内音写“短问句—休止—短答句”，两小节呼应，别连续爬音阶。
- 合成音色使用不同泛音、ADSR、轻微滤波、立体声短延迟；鼓居中、伴奏适度左右分布。编配有开头减法、中段进入、卡点段重音、结尾解决，不能把一个一秒loop直接重复30次。

合成分支是独立新曲，听感未必等于专业音乐生成，应在交付说明使用哪种方式。无论来源，只有检测真实音频与试听后才能说卡点和混音已检查。

动作音效：按事件表现场生成/制作独立短声音，不需要外链音效库。纸片抓取用细碎带通噪声，美工刀两次短锐“嚓”，抛物线用短带通whoosh，入桶为纸响+低短碰撞，进框为空心轻弹+网声，翻页为有包络的纸声，键入为短键击，Ctrl+Z为低一点的按键，滑块为轻摩擦+停靠click，磁吸为有冲击的短“咔”，导出撞击为低钝碰撞，完成为柔和两音提示。不要所有操作都配同一个“叮”。声效瞬态对齐实际接触/释放/入桶/到位帧；至少覆盖四次素材落地、两刀、释放与入桶、两次转场、逐字输入/撤销/改正、各次拖动与停靠、按钮、三次吸附、导出撞击与完成。

每个关键动作前约40–50ms开始让BGM短暂下降3–4dB，音效后约150–220ms平滑恢复；键击连串合并成一个ducking窗口，不每帧抽吸。音效不能被低音与高频镲淹没，也不能整片比音乐更吵。音乐不要重复叠加两份，混音不能简单硬剪到[-1,1]掩盖削波。

输出48kHz立体声，MP4用AAC。测量整片响度参考−15至−13 LUFS，编码后True Peak控制在−1dBTP左右或更低；数值只是参考，必须实际试听裁剪、翻页、磁吸和音乐是否能分辨。测完音频起点、强拍，再让beatMap与它一致。保存音乐和音效分轨，便于之后单独换曲。

八、角色保真与动作连接——优先约束

8.1 保留完整官方身体

官方精灵下载成功时，保留原角色的头部、躯干、双腿、身体比例、轮廓和色彩关系。静止、走路、思考、慌张、打字、开心和挥手，优先直接使用对应的完整官方精灵帧。不得只留下官方头部，再自行重画一个不同风格的身体。

需要延长手臂时，仅处理正在操作的一侧。保留原躯干、腿和另一侧手臂；先识别原肩部与手臂的实际像素范围，再局部遮除被替换的原手臂。延伸手臂的根部应进入原肩部下方，并由原身体轮廓覆盖连接处。不得切掉肩部形成白缝，不得遗留旧手掌、断线或形成第三只手。整张精灵不要因伸手而被拉伸。

新手臂使用连续曲线、柔和弯曲和向手腕逐渐变细的轮廓，颜色、描边粗细与阴影接近原精灵。手掌与手腕连成一个整体，避免大圆球手掌或等宽长条直接贴在原手上。手臂可以有适量卡通伸缩；较远目标需要身体先靠近，接近、伸手、抓握、回收均使用连续路径，不瞬移、不切换身体比例。结束时自然回到官方正常姿态。

屏外主角、手机舞台、素材缩略图、头像和片尾角色均复用同一套角色规则。身体变换后重新核对脚底与地面的关系。饰品只作覆盖层，不替换脸或身体。

8.2 先检查角色，再批量用于全片

制作包含正常站立、向左抓取、向右抓取、向上拉滑块、向下切割和收手的角色检查图。正常姿态与官方精灵并排查看，确认比例没有变化。至少对一次完整伸手及收手逐帧检查，并用局部放大图检查肩部、手腕和被握住的道具；只看全景缩略图不足以验收。

九、补充视觉与操作规则

1. 柴犬比例：正面头部以 x180 为对称中心，耳朵、眼睛、眉毛、脸颊和口鼻使用成对坐标或镜像结构。头部保持饱满圆润，脸部包围框高宽接近；避免宽扁脸和两侧轮廓无意失衡。尾巴可以不对称。保留 y70–160 字幕安全区，原有角色细节继续保留。

2. 先视频，后音乐轨：四段视频素材在93、113、133、153帧落位；音频轨此前只显示空轨背景，不显示完整波形。158–172帧从左到右连续展开音乐素材条和实际波形，展开边缘有轻微卷起及落定反馈。播放中的背景音乐仍从第0帧连续存在；“时间轴上的音乐素材出现”与“观众听到的背景配乐开始”是两个不同事件。

4. 颜色层次：保留纸色与墨线，以温暖黄、珊瑚橙、青绿、紫粉作有限主色。增加插画主体与背景的明暗、冷暖区分；工作台使用少量彩色分区和明确的交互强调色。不要通过给整个画面统一加高饱和度完成配色优化，正常状态的纸面、文字和肤色/毛色仍需自然清楚。

5. 气泡连接：气泡位置和尖角使用角色经过位移、跳跃、倾斜后的同一世界坐标。尖角指向头部上缘附近，随头部移动，不能使用固定左下尖角。气泡本体避开脸、手机、字幕、操作点与当前参数数值；先调整本体位置，再根据目标位置计算尖角。参数极端状态和角色运动中的中间帧也要检查。

6. 缩放即时可见：第579–591帧拖动缩放冲击时，手机内舞台应随旋钮逐渐放大，0%基础缩放为1.0，50%可用约1.21倍作为起点，再叠加短促衰减的重音反馈。拖动过程安排可见的效果示范，不能仅在之后播放时才出现效果。旋钮、数值、手机内容和冲击反馈共用一个状态；内容严格裁切在手机里，字幕与观看界面不随舞台一起放大。

十、片尾使用短视频观看界面

保持810–822帧进入片尾，823帧以后按原顺序回放落日、咖啡、柴犬、舞台。放大的手机加入抖音风格观看界面：顶部推荐/关注，右侧角色头像、关注按钮、点赞、评论、转发及音乐图标，底部作者、作品说明和简洁导航。

点赞数从约9.8万增长，在第866帧达到“10万+”，配短促爱心弹跳和少量上浮爱心。手机外可配一个清楚的点赞成果卡，作为片尾反馈。点赞是本动画内设计的演示效果。界面按钮避开主体眼睛、脸部和柴犬字幕；柴犬字幕仍在头顶，进入舞台后消失。所有四段必须有清楚可见的回放时间，不能为了加入界面而遮住主要作品。

十一、验收与版本保存

将验收分开记录：状态/数据正确、视觉正确、视频编码正确、声音听感正确。状态断言只能证明坐标和时序等数值，不能据此宣称角色自然或画面美观；响度值不能替代试听。

渲染前先检查素材和角色放大图，再检查关键动作连续帧；角色检查必须包含常态、伸手起点、最大伸展、操作过程和收手终点。共用组件修改后，检查它在工作台、手机舞台、缩略图和片尾的所有使用位置。最终画面检查尽量来自最终 MP4 解码帧，以避免旧截图与成片不一致。

每次交付另存不可覆盖的版本文件，例如 out/KK-Codex-30s-v1.mp4、v2.mp4、v3.mp4，同时可用 out/KK-Codex-30s.mp4 指向当前成片。面向用户的预览与下载必须链接具体版本。版本对应的联络表和验证记录也单独命名；更新默认输出前保留上一版，不因用户打开较早消息而让它悄悄播放新版。

交付只报告实际完成的检查；发现视觉缺陷先自主修复。保留可编辑工程、分轨和版本记录，允许用户直接比较修改前后。
